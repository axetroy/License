# License XML 如何工作

## 密钥角色

签发方保护 Ed25519 私钥。应用只分发可信公钥，并通过 `keyId` 选择对应密钥。私钥绝不能嵌入客户端应用或分发给用户。

## 签发流程

1. 构建并校验许可证载荷。
2. 将载荷序列化为 XML。
3. 使用 Canonical XML 1.0（不含注释）规范化 `<payload>`。
4. 使用 Ed25519 私钥签署规范化后的 UTF-8 字节。
5. 将 64 字节签名编码为 Base64 并写入 `signature` 元素。

## 验证流程

1. 严格解析 XML，并检查结构和大小限制。
2. 根据 `keyId` 查找可信公钥。
3. 规范化原始载荷元素并验证签名。
4. 只有密码学验证通过后，才检查产品、有效期和应用提供的机器指纹。

修改任何已签名字段都会导致签名验证失败。规范化后字节相同的 XML 语法差异不会影响签名；文本空白仍受签名保护，不应随意格式化。

## 安全边界

有效签名可证明载荷完整性，以及签发时持有对应私钥。离线验证无法获知远程撤销状态，无法阻止用户 Patch 应用，也无法保证系统时钟可信。功能执行、用量限制、指纹采集和撤销均由应用层负责。许可证内容可读，并未加密。
